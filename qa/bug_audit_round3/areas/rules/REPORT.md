The private-world probe keeps the acting player's exact `PlayerView`, public counts, used/discarded cards and visible knowledge. It varies unseen opponent hands/decks where existing observations permit, preserves inspected/known deck prefixes, reverses unseen deck suffixes and removes opponent-private observations. A pair count of 258 does not mean 258 changed private worlds: 219 actually differ. All 954 selected branches compare resulting public rules; private Radar observations and draws may legitimately differ. Canonical extra fields are checked against the complete authoritative output, not merely the public transition. Malformed requests are JSON-representable invalid shapes, types, ranges, identifiers and resolution arrays, with retained input checked after every rejection.

The Dart codec probe reads the exact TS-exported source states, then tests Dart's own decode/encode and restore/transition equivalence. It is a serialization and immutability invariant, not a fresh complete Dart/TS transition differential. The separate existing wire tests do execute fresh comparisons: 210 numeric-target requests (90 valid, 120 rejected) plus two malformed no-target/coercion requests, zero complete-state or complete-legal-set divergence. These requests are included in the 40 TAP tests, not additional tests to sum with them.

Battle perft traverses `DeckManager.apply` and `BattleRulesCore.legalActions`, using `PassAction` at card windows and no played card. Its oracle is the existing tracked `battle_contract/v1/perft.json`, with its preserved source `https://chessprogramming.org/Perft_Results`; no independent input was invented. All six positions run depths 1 and 2; initial, position3 and position4 also run depth 3. Expected leaf counts include 8,902 / 2,812 / 9,467 respectively. This checks actual Battle normal-move integration with the fixed reference counts; it does not independently prove all card rules or arbitrary game trees. There were no terminal nodes before the counted leaves.

Inspected source covers the 24 cards, special authorization geometry, restrictions, king safety, castling/EP/promotion application, terminal and public repetition accounting, authoritative hidden-state updates, and wire codecs. Canonical fixture paths exercise movement and knowledge-card phases, private resolution, effect lifetimes/removal and terminal paths; coverage is bounded by these inspected positions/actions.
